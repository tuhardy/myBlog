# MySQL 索引底层原理

> B+ 树、聚簇索引、回表、覆盖索引、最左前缀原则


## 为什么用 B+ 树而不是红黑树 / Hash

- **红黑树**：高度太高，磁盘 IO 次数多
- **Hash**：等值查询 O(1)，但范围查询、排序、模糊匹配全废
- **B+ 树**：矮胖（一般 3 层能存千万级），叶子节点用链表串起来方便范围扫描

## 聚簇索引 vs 非聚簇索引

以 InnoDB 为例：

| 类型 | 叶子节点存什么 |
|---|---|
| 聚簇索引（主键） | 完整的行数据 |
| 二级索引 | 主键值 |

所以用二级索引查出来的是主键，还要**回表**去聚簇索引拿完整行。

## 覆盖索引

一条查询要的列，刚好全部都在二级索引上，就不用回表。
关键标志：`EXPLAIN` 的 Extra 列出现 `Using index`。

## 最左前缀原则

联合索引 `(a, b, c)`：
- 走索引：`WHERE a = ?`、`WHERE a = ? AND b = ?`、`WHERE a = ? AND b = ? AND c = ?`
- 不走全：`WHERE b = ?`、`WHERE c = ?`（因为丢了最左的 a）

::: tip 怎么验证
永远把 `EXPLAIN` + `SHOW WARNINGS` 当成你的好朋友。
看 type 列至少 `range`，key 列是期望的索引，rows 越小越好。
:::
