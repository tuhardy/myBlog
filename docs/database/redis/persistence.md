# RDB vs AOF 持久化机制

> 快照 / 追加日志两种模式原理、优缺点和怎么组合用


## RDB（快照）

在某一时刻把内存里的数据「拍一张照」，写成一个压缩二进制文件 `dump.rdb`。

触发时机：
- 配置 `save 900 1`（900 秒内至少 1 次写就 save）
- 手动 `SAVE`（阻塞） / `BGSAVE`（fork 子进程，非阻塞）

**优点**：文件紧凑，恢复快，适合备份。
**缺点**：两次快照之间的数据可能丢。

## AOF（Append Only File）

把每条写命令追加到日志文件里，重启时重放所有命令恢复。

写磁盘频率：
- `always`：每条写都 fsync —— 最安全，最慢
- `everysec`（默认）：每秒刷一次盘
- `no`：交给 OS

**优点**：丢数据少（最多 1s）。
**缺点**：文件会越来越大，需要定期 `BGREWRITEAOF` 瘦身。

## 混合模式（Redis 4.0+，推荐开）

重写 AOF 时，先把内存当 RDB 写进文件头，再把增量命令追加到后面。
结果：**恢复速度接近 RDB，丢数据量接近 AOF**。

## 选型总结

| 需求 | 推荐 |
|---|---|
| 能接受几分钟数据丢失、备份为主 | 只用 RDB |
| 不能丢数据，单机 | AOF everysec + 混合 |
| 生产环境 | RDB + AOF |
