# 两数之和：从双循环到哈希表

两张写着 `3` 的卡片能凑出 `6`，那同一张卡片用两次行不行？如果你只检查数值之和，很容易得到一个看似正确、其实不合法的答案。

> **环境与安全**：先掌握 JavaScript 函数、数组下标和循环。沙盒仅运行同步 JavaScript，不是 Node.js；不支持 npm、import、网络、DOM、IndexedDB、文件系统、后端或真实 Linux。只有你点击运行才执行，不自动载入远端代码、不保存草稿、不收集遥测。不要输入秘密或不明来源代码。编辑器需要客户端 JavaScript，正文与参考代码可静态阅读。

> - 卡片上的数字 → `nums` 中的元素，用来相加。
> - 卡片的固定编号 → 原始数组下标，必须返回两个不同编号。
> - 已见卡片登记簿 → `Map`，保存已经见过的数值及其下标。

比喻不改变题意：你交回的是编号，不是卡片上的数值。完成本页后，你应能独立写出两种解法，解释重复值和零的边界，并区分算法复杂度与一次运行耗时。

## 一、先把题意说准确

编写同步函数 `function twoSum(nums, target)`。给定整数数组 `nums` 和整数目标值 `target`，返回一个恰好包含两个下标的数组，使对应元素之和等于目标值。

- 输入保证**有且只有一组解**。本题不扩展无解或多解的返回约定。
- 下标从 `0` 开始，必须是**原始数组**中两个不同且有效的位置，不能重复使用同一个元素。
- 下标必须为 `number` 类型且为整数；数字字符串如 `["0", "1"]`、小数、越界下标都不接受。
- 下标顺序不限：有效答案 `[0, 1]` 与 `[1, 0]` 等价。不是返回对应的两个数值。
- 直接返回数组，不写 `export` 或 `module.exports`，不返回 Promise 或其他 thenable，不使用 `async` 入口。

参数与返回值遵循[总览的同步函数与 JSON 契约](./#同步函数契约)。有且只有一组解、返回两个下标及顺序不限都是**本题专属规则**，不适用于其他题目；本题使用下标语义判题，而非数组逐项精确比对。

### 本题的 5 个固定用例

| 用例 | `nums` | `target` | 一种期望下标 | 要检查的边界 |
| --- | --- | --- | --- | --- |
| 基础配对 | `[2, 7, 11, 15]` | `9` | `[0, 1]` | 返回编号，不是 `[2, 7]` |
| 答案不在开头 | `[3, 2, 4]` | `6` | `[1, 2]` | 不能写死前两个位置 |
| 相同数值、不同下标 | `[3, 3]` | `6` | `[0, 1]` | 两个 `3` 是不同元素 |
| 负数参与配对 | `[-3, 4, 3, 90]` | `0` | `[0, 2]` | 补数也可能为负数 |
| 两个零 | `[0, 4, 3, 0]` | `0` | `[0, 3]` | 下标 `0` 不能被真假值判断误丢弃 |

允许改动当前调用拿到的参数副本，但答案仍按原始数组校验。直接排序后返回排序后的下标会改变编号含义；若选择排序方案，必须同时保留原始下标。

## 二、先运行一份正确的双循环

编辑器的初始代码如下。它枚举所有 `i < j` 的位置组合，因此不会重复使用同一元素，也不会遗漏合法配对，按题意应通过全部 5 例。

```javascript
function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) {
        return [i, j]
      }
    }
  }
  return []
}
```

末尾 `return []` 只是防御性收尾；在本题保证有解且实现正确的条件下不会走到这里，不代表题目新增了无解语义。

**操作**：保持初始代码，点击运行。**观察**：逐例核对输入、期望、实际与状态，预期 5 例全部通过。**原理**：外层选定一张卡片，内层只检查它后面的卡片；编号不同由 `j = i + 1` 保证。

## 四、用登记簿少做重复查找

双循环每拿到一张卡片，都重新寻找另一张。换个问题：当前值为 `value`，你需要的另一张是不是已经登记过的 `target - value`？

按从左到右的顺序，每步只做三件事：

1. 计算补数 `target - nums[i]`。
2. 查询登记簿。如果补数已经出现，返回它的旧下标和当前下标。
3. 如果没找到，才把当前数值及下标记入 `Map`。

以 `[3, 2, 4]`、目标 `6` 为例：先查 `3`，登记簿为空，登记 `3 → 0`；再查 `4`，未找到，登记 `2 → 1`；最后查 `2`，得到下标 `1`，返回 `[1, 2]`。

**先查再存**确保登记簿里只包含当前位置之前的卡片，避免拿当前卡片和自己配对。对 `[3, 3]`，第二个 `3` 能找到第一个；对两个零，判断键是否存在应使用 `Map.has`，不能用 `if (seen.get(complement))`，因为有效下标 `0` 是假值。

先自己改写，再展开参考。沙盒不会自动切换解法；需要你将参考代码替换到上面的同一个编辑器中。

```javascript
function twoSum(nums, target) {
  const seen = new Map()
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i]
    if (seen.has(complement)) {
      return [seen.get(complement), i]
    }
    seen.set(nums[i], i)
  }
  return []
}
```

循环开始时，`seen` 仅记录已遍历位置的数值与某个对应下标。命中补数时，旧下标严格小于当前下标，且二者数值之和等于目标，因此答案合法。如果唯一解的位置为 `a < b`，遍历到 `b` 时必能查到需要的数值。题意保证有解，因此正确实现不会走到末尾的 `return []`。

## 五、复杂度与边界复盘

令 `n` 为数组长度，额外空间不计输入和固定长度的返回数组。

| 解法 | 时间复杂度 | 额外空间 | 推导条件 |
| --- | --- | --- | --- |
| 双循环 | 最坏 `O(n²)` | `O(1)` | 最多检查 `n(n - 1) / 2` 对位置，找到解可提前返回 |
| 哈希表 | 通常分析为平均 `O(n)` | `O(n)` | 假设 `Map` 查询与写入平均 `O(1)`，最多遍历 `n` 个元素并保存线性数量的记录 |

JavaScript 规范不承诺所有引擎、所有输入下 `Map` 操作都为最坏 `O(1)`，所以不要把哈希表的平均分析当作无条件最坏保证。这里也没有自动测量复杂度：只有几个小样例时，启动、调度和输出开销会干扰耗时比较。

练习并写下理由：

1. 为什么不能先 `seen.set(nums[i], i)`，再查询补数？用 `[3, 3]` 举出重复下标的反例。
2. 为什么 `if (seen.get(complement))` 会漏掉零号位置？用 `[0, 4, 3, 0]` 解释，并改用 `has`。
3. 若先对 `[3, 2, 4]` 排序，再返回排序后的下标，为什么不满足原始编号契约？
4. 能否只凭 5 例通过就宣称对所有输入正确？请分别说出双循环的枚举范围和哈希表的循环不变量。
