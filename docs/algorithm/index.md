# 算法沙盒：先配对，再解释为什么

一排有编号的数字卡片里，哪两张恰好凑出目标值？你可以挨个试，也可以记住已经见过的卡片。答案相同，寻找答案的工作量却不同。

> **环境与安全**：你需要 JavaScript 数组、循环和函数基础，以及支持 Web Worker 的现代浏览器。这里只运行你主动输入并点击运行的本地教学代码，不是 Node.js 或真实 Linux。总览是静态阅读页，编辑器位于题目页；正文和限制说明无需启动沙盒即可阅读。不要输入秘密或运行来源不明的恶意代码。

> - 卡片上的数字 → 数组元素的值，用于计算是否达到目标。
> - 卡片的固定编号 → 原始数组下标，才是需要返回的答案。
> - 已见卡片登记簿 → 哈希表，记录数值和下标，帮助寻找另一张卡片。

比喻只帮助你区分“值”和“位置”；判题依靠明确的函数契约，不会理解你寻找卡片的意图。

## 操作 → 观察 → 原理

1. **操作**：进入[两数之和](./two-sum)，保留初始双循环函数，点击运行。编辑器不会自动执行代码，也不会从 URL 或远端自动载入待执行代码。
2. **观察**：核对每例的输入、期望下标、实际结果、状态、日志与耗时。按题意，初始代码应通过全部 5 例；这是预期验收结果，不是运行性能报告。
3. **原理**：判题检查答案契约，而不是要求你的源码与参考解法一致。反向返回两个有效下标仍可通过。
4. **再实验**：只改一处，再运行并解释变化。停止会终止当前运行；重置会先停止，再恢复初始代码并清空结果。没有保存草稿或收集遥测的功能，请自行保留需要的代码。

每次运行使用新的 Worker，每个用例使用独立的 SES Compartment 和输入副本。你可以修改当前参数副本，但不能靠顶层变量跨用例累计状态，也不应依赖上一轮的结果。

## 同步函数契约

入口是 `function twoSum(nums, target)`，直接返回一个包含两个下标的数组，不使用 `export`、`module.exports` 或命令行输入。

- 输入保证**有且只有一组解**，不定义无解时的返回语义。
- 下标从 `0` 开始，必须指向**原始数组**中两个不同且有效的位置。
- 下标必须已经是 `number` 类型的整数；`["0", "1"]` 这样的数字字符串不接受。
- 两个位置的数值之和必须等于 `target`；返回下标的顺序不限。
- 仅支持同步返回；`async` 函数、Promise 和其他 thenable 返回值不受支持。

## 如何读结果

| 状态 | 含义与下一步 |
| --- | --- |
| 尚未运行 / 运行中 | 尚无完成结果；不要把未执行用例算成失败或通过 |
| 通过 | 本例满足题意；全部固定用例通过仍不能代替一般正确性证明 |
| 答案错误 | 检查返回类型、下标范围、下标是否重复，以及对应数值之和 |
| 语法错误 | 代码未能通过解析或 SES 语法限制；先检查入口和语法 |
| 运行时错误 | 执行时抛错、入口缺失或不是函数、返回异步结果等；主动抛出 `SyntaxError` 也属于运行时错误 |
| 超时 | 整批执行超过预算后被终止；检查循环是否推进、是否存在无界工作 |
| 输出超限 | 返回值、日志或错误展示超过预算，或超出格式化结构限制；减少输出 |
| 已停止 | 你终止了运行；已完成结果保留，后续用例未运行，可再次运行 |
| 代码无效 | 空白或超长代码未被接受；修改后重试 |
| 执行器错误 | Worker 加载、初始化或通信异常；不等于算法答案错误，记录提示后重试 |

超时或停止时，已完成用例保留，当前用例标明超时或已停止，后续用例保持未运行。

## 资源预算

以下来自当前沙盒配置。`1 KiB = 1024` 字节，字节预算按 UTF-8 计算；代码长度单独按 UTF-16 代码单元计算。

| 项目 | 上限与计量范围 |
| --- | --- |
| 代码 | 32768 个 UTF-16 代码单元，不等于 32768 字节；部分字符占两个代码单元 |
| 输入 | 整个请求的 JSON 输入合计 64 KiB；当前题库固定为 5 例，协议最多允许 20 例 |
| 展示输出 | 整次运行累计 64 KiB，包含结果、日志和错误文本，不是每例各 64 KiB |
| 日志 | 整次运行累计 16 KiB，同时占用上述 64 KiB 总输出预算，不是额外额度 |
| 错误文本 | 4 KiB 限额，并计入总输出预算 |
| Worker 启动 | 从创建 Worker 起最多等待 10 秒，覆盖资源加载和初始化 |
| 整批执行 | Worker 就绪后整轮累计 3 秒，不是每例 3 秒；顶层代码、函数调用和输出处理均在执行边界内 |

输出还受日志条数、遍历深度和节点数约束，因此未到字节上限也可能被限制。显示的耗时用于定位一次运行，不是算法基准测试，不能据此宣称哈希表在这些小样例上快了多少倍。

## 能力与安全边界

- **支持**：浏览器内同步 JavaScript 算法、数组与 `Map` 等语言内建对象、受限的 `console.log` / `warn` / `error` 日志。
- **不支持**：用户代码访问网络、静态或动态 `import`、npm 包、DOM、IndexedDB、Node.js API、文件系统、后端服务或真实 Linux。页面自身加载编辑器和 Worker 静态资源，不代表用户代码获得网络能力。
- **SES 差异**：执行环境采用严格模式与冻结的内建对象，不提供可用的随机数和时钟能力；保守的导入语法拒绝也可能影响含特殊文本的代码。它不是普通网页的全局环境，也不是绕过隔离的练习场。
- **隔离不等于无限安全**：SES 限制能力访问，Worker 可被终止，但它们仍依赖共享浏览器引擎，**没有独立内存硬配额**。内存耗尽、浏览器崩溃或后台调度可能影响终止时机，3 秒不是严格实时保证。这不是安全的多租户服务器，不适合运行不可信的恶意程序。
